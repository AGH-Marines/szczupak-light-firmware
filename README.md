# STM32 Project Template

This  template is intended for use in future projects. It is designed to separate application code from the target microcontroller.
Components are structured to support unit testing, allowing application logic to be developed and verified without relying on tests performed on the target platform.

---

## Requirements

* STM32CubeMX
* CMake 3.25 or newer
* Ninja
* ARM GNU Toolchain
* OpenOCD
* GDB Multiarch
* VS Code
* CMake Tools, C/C++, and Cortex-Debug extensions

---

## Creating a Project

1. Select **Use this template** on GitHub.
2. Create and clone a new repository.
3. Configure the microcontroller in STM32CubeMX.
4. Select **CMake** as the project toolchain.
5. Generate the project directly into the repository root.
6. Set the OpenOCD target in `Config/project-config.cmake`.

---

## Building

Debug build:

```bash
Tools/build.sh Debug
```

Release build:

```bash
Tools/build.sh Release
```

Build files are stored in:

```text
build/Debug/
build/Release/
```

Firmware builds are not available before generating the project with STM32CubeMX.

---

## Flashing

Flash an existing build:

```bash
Tools/flash.sh Debug
```

Build and flash:

```bash
Tools/build_flash.sh Debug
```

OpenOCD settings are stored in:

```text
Config/project-config.cmake
```

---

## Debugging in VS Code

After opening the project for the first time:

1. Run `CMake: Select Configure Preset`.
2. Select `Debug`.
3. Run `CMake: Configure`.
4. Run `CMake: Select Launch Target`.
5. Start debugging with `F5`.

---

## Local Unit Tests

```bash
Tools/test.sh
```

Unit tests use the local compiler and can be performed before generating the project with STM32CubeMX.

---

## Creating a Component

```bash
Tools/create_component.sh ComponentName file_name
```

Naming convention:

```bash
Tools/create_component.sh CommandParser command_parser
```

The script creates the component sources, CMake configuration, and a basic Unity test.


---

## Directories

`App/`

  > Application logic specific to the project.

`BSP/`

  > Hardware abstraction between the application and STM32 HAL.

`Components/`

  > Independent modules that can be tested on local system.

`Config/`

  > Manually maintained project configuration.

`Tools/`

  > Build, test, flash, and component generation scripts.

`Core/`

  > Code generated by STM32CubeMX.

`Drivers/`

  > HAL, CMSIS, and device drivers generated by STM32CubeMX.

`Middlewares/`

  > Middleware generated or added by STM32CubeMX.

`cmake/`

  > Toolchain and CMake files generated by STM32CubeMX.

`.vscode/`

  > Shared VS Code build, debug, and formatting configuration.
